## امکانات

- رله **VLESS WebSocket** و **XHTTP** روی همان سرویس
- ساخت خودکار ساب چندپروتکلی
- مسیر مخفی ادمین (کسی با لینک ساب، آدرس پنل را پیدا نمی‌کند)
- صفحه ساب کاربر: مصرف، نمودار، QR، دانلود نرم‌افزار، AmneziaWG، پروکسی تلگرام
- WireGuard / AmneziaWG از طریق **Cloudflare WARP** (فایل `.conf`)
- مدیریت حجم، انقضا، محدودیت IP / اتصال / سرعت
- ربات تلگرام (مدیریت + فروش)
- ذخیره پایدار روی Volume مسیر `/data`
- اولویت اتصال خروجی **IPv4** (IPv6 اختیاری)

## پروتکل‌هایی که واقعاً کار می‌کنند

| پروتکل | وضعیت روی Railway |
|--------|-------------------|
| **VLESS WebSocket** | رله واقعی پنل |
| **XHTTP** (Packet / Stream Up / Stream One) | رله واقعی پنل |
| **WireGuard** | کانفیگ واقعی WARP (فایل `.conf`) |
| **AmneziaWG** | کانفیگ واقعی WARP + Junk (فایل `.conf`) |
| VMess / Trojan / Shadowsocks / SOCKS / HTTP | روی این هاست رله ندارند (نیاز سرور جدا) |
| Hysteria2 / TUIC | نیاز UDP؛ روی دیپلوی HTTP معمولی Railway مناسب نیست |

در ساخت خودکار، فقط پروتکل‌های قابل‌کار به‌عنوان کانفیگ ساب ساخته می‌شوند تا لینک‌های فیک داخل ساب نرود.

## دیپلوی روی Railway (گام‌به‌گام)

1. مخزن را در GitHub Fork یا آپلود کنید.
2. در [Railway](https://railway.app) → **New Project** → Deploy from GitHub.
3. سرویس ساخته شد؛ یک **Volume** بسازید و روی مسیر زیر mount کنید:

   ```text
   /data
   ```

4. از بخش **Networking** برای سرویس، **Generate Domain** بزنید تا دامنه عمومی فعال شود.
5. (اختیاری) متغیرهای محیطی را طبق جدول پایین ست کنید.
6. Deploy را صبر کنید تا لاگ چیزی شبیه این نشان دهد:

   ```text
   PANEL LOGIN: /panel-admin/login
   ```

7. در مرورگر بروید:

   ```text
   https://YOUR-DOMAIN.up.railway.app/panel-admin/login
   ```

   اگر `PANEL_PATH` را عوض کرده باشید، همان مقدار را جای `panel-admin` بگذارید.

## مسیر مخفی پنل (PANEL_PATH)

پنل ادمین پشت یک **پیشوند مخفی** است تا با دیدن لینک ساب (`/sub-group/...`) کسی به صفحه لاگین نرسد.

### مقدار پیش‌فرض

```text
panel-admin
```

آدرس ورود پیش‌فرض:

```text
https://DOMAIN/panel-admin/login
```

داشبورد:

```text
https://DOMAIN/panel-admin/
```

### مسیرهایی که مخفی نیستند (عمدی)

این‌ها باید عمومی بمانند تا کلاینت و کاربر کار کنند:

| مسیر | کاربرد |
|------|--------|
| `/sub-group/{uuid}` | لینک ساب + صفحه مصرف |
| `/sub/{uuid}` | ساب تکی |
| `/ws/{uuid}` | تونل VLESS |
| `/xhttp-siz10/...` | تونل XHTTP |
| `/api/public/...` | API عمومی ساب / Amnezia / MTProto |
| `/health` | سلامت سرویس |

هر مسیر ادمین و API مدیریت فقط زیر `/{PANEL_PATH}/...` در دسترس است. ریشه سایت (`/`) پنل را نشان نمی‌دهد.

### روش ۱ — متغیر محیطی (پیشنهادی هنگام دیپلوی)

در Railway → Variables:

| کلید | مثال | توضیح |
|------|------|--------|
| `PANEL_PATH` | `my-secret-panel` | بدون اسلش اول/آخر |

بعد از دیپلوی:

```text
https://DOMAIN/my-secret-panel/login
```

### روش ۲ — از داخل تنظیمات پنل

بعد از ورود: **تنظیمات → مسیر مخفی پنل** → مقدار جدید → ذخیره.  
مقدار در Volume داخل فایل تقریباً به این شکل نگه داشته می‌شود:

```text
/data/panel_path.txt
```

### اولویت خواندن مسیر

1. متغیر `PANEL_PATH` (اگر ست شده باشد)
2. مقدار ذخیره‌شده در Volume
3. در غیر این صورت: **`panel-admin`**

### نکات امنیتی

- مسیر را شبیه پسورد انتخاب کنید (طولانی و تصادفی بهتر است).
- مسیر را در کانال عمومی نفرستید.
- عوض کردن مسیر، لینک‌های ساب کاربران را خراب **نمی‌کند** (ساب زیر `/sub-group/` است).

## اولین ورود و رمز ادمین

### حالت پیش‌فرض (بدون متغیر رمز)

1. بروید به `https://DOMAIN/panel-admin/login`
2. اگر هنوز رمزی ذخیره نشده باشد، **فرم ساخت رمز اول** می‌آید.
3. یک رمز قوی بگذارید و وارد شوید.

### رمز از قبل با متغیر محیطی

| کلید | مقدار |
|------|--------|
| `ADMIN_PASSWORD` | رمز دلخواه شما |

در این حالت همان رمز برای ورود استفاده می‌شود.

### فراموشی رمز

در Railway → Variables موقتاً بگذارید:

| کلید | مقدار |
|------|--------|
| `RESET_PASSWORD` | `1` |

یک‌بار Redeploy کنید تا فرم ساخت رمز دوباره بیاید. بعداً این متغیر را حذف کنید.

## متغیرهای محیطی

همه **اختیاری** هستند.

| متغیر | پیش‌فرض | توضیح |
|--------|---------|--------|
| `PANEL_PATH` | `panel-admin` | مسیر مخفی ادمین |
| `ADMIN_PASSWORD` | — | رمز اولیه / ثابت ادمین |
| `RESET_PASSWORD` | — | با `1` ریست فرم رمز |
| `PUBLIC_HOST` | دامنه Railway | هاست داخل لینک کانفیگ |
| `PUBLIC_PORT` | `443` | پورت داخل لینک |
| `PUBLIC_SECURITY` | `tls` | `tls` یا `none` |
| `PREFER_IPV6` | خاموش | اگر `1` باشد اولویت با IPv6 است |
| `TELEGRAM_BOT_TOKEN` | — | توکن ربات (یا از UI) |
| `TELEGRAM_ADMIN_IDS` | — | آیدی عددی ادمین‌ها |
| `MTPROTO_ENABLED` | — | فعال‌سازی نمایش پروکسی تلگرام |
| `MTPROTO_SERVER` | — | هاست TCP Proxy سرویس MTProto |
| `MTPROTO_PORT` | `443` | پورت عمومی MTProto |
| `MTPROTO_SECRET` | — | Secret پروکسی تلگرام |

## ساخت ساب و کانفیگ

### ساخت خودکار چندپروتکلی

1. وارد پنل شوید.
2. بخش ساخت خودکار / Multi را باز کنید.
3. نام ساب را بنویسید.
4. فقط پروتکل‌های **VLESS** و **XHTTP** را برای کانفیگ ساب تیک بزنید (این‌ها در v2rayNG و مشابه کار می‌کنند).
5. در صورت نیاز **تعداد AmneziaWG** را بین ۱ تا ۶ بگذارید (۶ = همه پروفایل‌های سبک تا سنگین).
6. حجم / روز / محدودیت‌ها را در صورت نیاز پر کنید و بسازید.

خروجی:

- لینک یکتا: `https://DOMAIN/sub-group/{UUID}`
- همان لینک هم برای **مرورگر** (صفحه مصرف) و هم برای **کلاینت** (بدنه ساب) است.

### پروفایل‌های امنیتی ساخت

| پروفایل | معنی تقریبی |
|---------|-------------|
| normal | بدون محدودیت اضافه |
| balanced | محدودیت IP/اتصال متعادل |
| gaming | اتصال محدودتر |
| speed | تمرکز روی سرعت |
| stable | پایدارتر |
| maximum | حداکثر باز |

## AmneziaWG / WireGuard (WARP)

پنل از APIهای عمومی WARP کانفیگ می‌گیرد و فایل استاندارد می‌سازد (نه رله UDP خود Railway).

### پروفایل‌های Amnezia (Junk)

| پروفایل | مناسب برای |
|---------|------------|
| Light | شبکه معمولی / وای‌فای · سرعت بهتر |
| Medium | فیلترینگ متوسط · موبایل |
| Heavy | فیلترینگ شدید |
| Ultra | DPI خیلی قوی |
| Mobile | ۴G/۵G · MTU پایین‌تر |
| WiFi | وای‌فای پایدار · MTU بالاتر |

در صفحه ساب: **کپی کانفیگ** یا **دانلود `.conf`**  
در اپ **AmneziaVPN** یا کلاینت WireGuard سازگار ایمپورت کنید.

> ساب‌های ساخته‌شده **قبل** از فعال شدن این قابلیت، فایل AWG ندارند؛ یک ساب جدید بسازید.

## پروکسی تلگرام (MTProto)

MTProto داخل همین پروسه VLESS اجرا **نمی‌شود**. باید یک سرویس جدا (مثلاً `telegrammessenger/proxy`) با **TCP Proxy** روی Railway داشته باشید؛ پنل فقط لینک `t.me/proxy` می‌سازد و به کاربر نشان می‌دهد.

1. سرویس MTProxy را بالا بیاورید و TCP Proxy بگیرید (مثال: `xxx.proxy.rlwy.net:40630`).
2. در پنل → **تنظیمات → پروکسی تلگرام** سرور، پورت، Secret را وارد کنید.
3. می‌توانید چند پروکسی اضافه کنید.
4. تیک نمایش در صفحه ساب را بزنید و ذخیره کنید.

اگر خالی بماند، ساب بدون پروکسی تلگرام عادی کار می‌کند.

## صفحه عمومی ساب کاربر

آدرس:

```text
https://DOMAIN/sub-group/{UUID}
```

شامل:

- وضعیت، تعداد کانفیگ، مصرف (گیگابایت)، انقضا
- نوار و نمودار مصرف
- **QR کد** برای اسکن در کلاینت
- کپی لینک ساب
- لینک دانلود اپ (ویندوز / مک / اندروید / iOS)
- بلوک AmneziaWG در صورت وجود
- بلوک پروکسی تلگرام در صورت فعال بودن

کلاینت‌هایی مثل v2rayNG / Hiddify / Streisand با User-Agent غیرمرورگر، بدنه **Subscription** می‌گیرند؛ مرورگر همان صفحه HTML را می‌بیند.

## شبکه، IPv4 و TCP Proxy

### اولویت IP

پیش‌فرض رله: **اول IPv4، بعد IPv6**.  
برای اجبار IPv6: `PREFER_IPV6=1`.

### TCP Proxy / اندپوینت عمومی

اگر در Railway برای سرویس پنل TCP Proxy دارید، در تنظیمات شبکه پنل می‌توانید:

- `PUBLIC_HOST` = هاست proxy  
- `PUBLIC_PORT` = پورت عمومی  
- `PUBLIC_SECURITY` = `tls` یا `none`

در ساخت چندپروتکلی، در صورت تفاوت با دامنه اصلی، کانفیگ دوم با اندپوینت Proxy هم ساخته می‌شود.

### نشت IP

روی VLESS، DNS و WebRTC سمت **کلاینت** باید قفل شوند (مسیریابی کامل از پروکسی، قطع WebRTC). سرور به‌تنهایی نشت مرورگر را صفر نمی‌کند.

## ربات تلگرام و فروش

1. از [@BotFather](https://t.me/BotFather) ربات بسازید و توکن بگیرید.
2. آیدی عددی خود را از ربات‌های شناسه بگیرید.
3. در پنل بخش ربات تلگرام، توکن و Admin ID را وارد کنید **یا** با env:

   ```text
   TELEGRAM_BOT_TOKEN=...
   TELEGRAM_ADMIN_IDS=123456789
   ```

4. برای فروش: تنظیم کارت، تعریف محصول، تأیید رسید توسط ادمین.

## عیب‌یابی

| مشکل | کار پیشنهادی |
|------|----------------|
| صفحه اصلی ۴۰۴ است | طبیعی است؛ بروید به `/{PANEL_PATH}/login` |
| لاگین ۴۰۴ | مسیر مخفی را در لاگ Deploy چک کنید: `PANEL LOGIN: /.../login` |
| رمز اشتباه / گیر کرده | `RESET_PASSWORD=1` و یک‌بار Redeploy |
| کانفیگ‌ها بعد از دیپلوی پاک شدند | Volume روی `/data` وصل نیست |
| پینگ دارد ولی سایت باز نمی‌شود | کلاینت، DNS، و قطع WebRTC را چک کنید؛ از VLESS یا XHTTP واقعی استفاده کنید |
| XHTTP تاخیر ۱- | مسیر و TLS دامنه Railway را بررسی کنید؛ گاهی فقط VLESS-WS پایدارتر است |
| Amnezia در ساب نیست | ساب را **بعد از** آپدیت بسازید و تعداد AWG > 0 بدهید |
| دانلود `.conf` | از دکمه دانلود صفحه ساب استفاده کنید (Blob)؛ یا متن را کپی کنید |
| Trojan/VMess در ساب | عمداً به‌عنوان رله این هاست ساخته نمی‌شوند |
